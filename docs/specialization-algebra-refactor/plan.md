# Specialization-algebra refactor

## Problem

`src/specialization/speculative-clone.ts` and the chain/retirement machinery
in `src/specialization/framework/` conflate several orthogonal concerns into
overloaded functions. Two latent bugs already result; more will follow as
narrowing axes deepen beyond the current depth-1 regime.

## Findings

### Latent bugs in current code

1. **Ancestor-fork drop.** `specializedBodyFor` at `src/specialization/speculative-clone.ts:117`
   early-returns `undefined` when `!contextIsEntrySpecializable(unit, context)`,
   before reading `context.visibleBody(unit)` at line 133. Ancestor-published
   bodies (e.g. memoization forks at an entry-specializable parent) are
   silently dropped whenever any descendant layer carries a non-param
   assumption. The function's own docstring (lines 110-113) describes the
   intended behavior, which the code contradicts.

2. **Non-transitive retirement.** `Worklist.isRetired` at
   `src/specialization/framework/worklist.ts:404-406` is pointwise
   `retiredNodes.has(node)`. No ancestor walk. Today the only transitive
   check lives at one consumer —
   `src/specialization/speculative-clone.ts:122-125` — which externalizes
   the filter semantics. Every other caller that queries `isRetired`
   directly gets the wrong answer for retired-ancestor chains. The
   worklist comment at `worklist.ts:426-431` acknowledges the cascade is
   missing and justifies it by "current narrowing set is single-axis,
   depth-1."

3. **Retirement does not cascade.** `retireChain` at `worklist.ts:432-448`
   retires the passed node only. Descendant forks, descendant memo
   buckets, and descendant entries in `futureDispatchContext` are left
   intact. Latent today; active as soon as chain depth > 1.

4. **CSE harness skips retirement entirely.** `tests/specialization/harness/jit-runners.ts:115`
   calls `specializedBodyFor(...)` without the `isRetired` argument. Any
   retirement-driven test regression would miss this path.

5. **Interner replace-on-conflict is dead.** `ContextInterner.extend`
   (`assumption-chain-interner.ts:80-102`, `rebuildWith` at ~227) silently
   replaces on conflicting `(narrowing, key)` values. The observation
   path at `worklist.ts:1076-1088` always does retire → `excludeAssumption`
   → `extendContext`, so `rebuildWith`'s replace branch is unreachable
   from production code. The behavior is load-bearing only for a handful
   of tests that build chains by hand.

### Algebra

The structure is a **bounded meet-semilattice**, not a lattice.

- Chains are canonical finite partial maps `(Narrowing, Key) ⇀ Value`,
  canonicalized by the interner.
- Partial order: `X ⊑ Y` iff `dom(X) ⊆ dom(Y)` and `X` agrees with `Y` on
  the overlap.
- Bottom `⊥` is the empty map (`empty` / `ROOT_CONTEXT`).
- Meet `⊓` is total: intersection of the maps, keeping entries that
  agree. This is `without` iterated over disagreements.
- Join `⊔` is **partial**: undefined when two chains bind the same
  `(narrowing, key)` to different values. No explicit ⊤ exists in code;
  `extend` now asserts on conflict, so the partiality is explicit.

Each canonical chain now carries a content-addressed
`bindings: Map<Narrowing, Map<key, Assumption>>` built at intern-time.
All algebraic operations are set operations on this map:

- `at(s, n, k)` is O(1) map lookup.
- `leq(x, y)` is O(|x|) subset-with-agreement — detects algebraic
  supersets regardless of trie build order. This is the key
  correctness property: a chain `y` built via a rebuild path (new
  assumption sorts earlier than parent's tip) algebraically contains
  `x` even though `y.parent → empty` does not pass through `x`.

Retirement is an **upward-closed filter** generated by stored minimal
retirement events:

```
retired(c) ⟺ ∃ r ∈ R. leq(r, c)
```

`R` holds minimal generators only; membership is computed by algebraic
`leq` on the fly. No eager cascade enumeration is needed — a previous
draft of this plan proposed enumerating supersets via a trie DFS, but
trie descent skips rebuild-path siblings, so the enumeration was
incorrect in the general case. Lazy membership via algebraic `leq` is
both correct and simpler.

`visibleBody` is not a lattice operation. It is a
**nearest-ancestor-with-a-section** lookup over a presheaf-shaped store
`(Unit, Chain) ⇀ Body`. Retirement-aware `visibleBody` walks ancestors
and skips any where `isRetired` returns true.

### Non-obvious consequences

- Naming: `Chain` is misleading. An assumption-set is not a chain in the
  order-theoretic sense — siblings are incomparable. `AssumptionSet`
  reads truer. The module is named `assumption-algebra`.
- `project(c, n, k)` (considered and rejected) collides with the
  worklist's existing use of "project" for context/key morphisms
  (`worklist.ts:492`, `:790`). Use `without`.
- `leq(x, y)` has argument order opposite to the previous
  `hasAncestor(ctx, anc)`. Call-site rewrites swap arguments (tests
  only — no production caller depended on parent-path ancestry).
- `extend` made assertion-strict on conflicts surfaces any hand-built
  chain in tests that relied on replace; those tests rewrite as
  `extend(without(c, n, k), n, k, v')` which is both literally what the
  worklist does and self-documenting.
- Each canonical chain carrying `bindings` adds O(depth) memory per
  interned node for O(1)/O(|x|) algebraic ops. Intern time adds one
  Map clone. Negligible compared to forked body cost.

## Rationale for key decisions

### Why "meet-semilattice with ⊥", not "lattice"

Total join would require either (a) enforcing compatible extends everywhere
or (b) adding an explicit ⊤ ("contradiction") value. (a) is what the
worklist already does via retire+exclude+extend, so join appears total
on that path — but the algebra itself is partial. (b) would force every
body-read site to guard against ⊤, a tax disproportionate to the single
case ("unreachable chain") it names. Keep the semilattice story honest;
let `extend` be partial; retire the chain when the worklist observes
a conflict. That's the current flow; naming it is enough.

### Why rename rather than comment

"Code should be self-documenting as a lattice, no comment-slop that XYZ
is a lattice operation" was the explicit instruction. Names carry the
story only when each operation's name coincides with its algebraic
role. `leq` / `without` / `extend` / `extensions` / `at` read straight
as algebra; `hasAncestor` / `excludeAssumption` / `extendContext` /
`findAssumption` read as domain-specific imperatives and need prose to
explain the algebra they implement.

### Why retirement collapses to one PR

An earlier draft split retirement into "cascade logic" (PR 3) and
"eviction-subscriber protocol" (PR 4). With algebraic `leq` and lazy
`isRetired` membership, there is no cascade logic — `retire(r)` just
adds `r` to the minimal-generator set. Nothing enumerates supersets.
Body eviction at retired descendants is lazy (skipped on next
`visibleBody` query). The framework→analysis coupling that PR 4 was
meant to address still exists (`memoIdFor` / `guardKeyFromGuards` /
`purityBlockAnalysis` imports from the worklist) but is not introduced
or worsened by the retirement module, so the cleanup is a separate
follow-up rather than a required step of this refactor.

### Why PR 5 is scoped to three algebraic suites plus explicit triage

The branch has ~20 deleted test files visible in `git status`. Three
new algebra-shaped suites do not replace that coverage. The correct
answer is not to expand PR 5 indefinitely but to split coverage work
from algebra work: PR 5 adds the new algebra-as-property suites; a
separate coverage-triage PR enumerates every deleted file and marks
each as ported / superseded / intentionally-dropped with justification.

## Plan

Five PRs (PR 4 collapsed into PR 3 given the simpler filter). Each
independently revertable.

### PR 1 — Extract `assumption-algebra.ts`; add content-addressed bindings [DONE]

**New file:** `src/specialization/framework/assumption-algebra.ts`.

Public surface:

```ts
export type AssumptionSet
export const empty: AssumptionSet
export function extend(s: AssumptionSet, n: Narrowing, k, v): AssumptionSet   // strict on conflict
export function without(s: AssumptionSet, n: Narrowing, k: unknown): AssumptionSet
export function at<V>(s: AssumptionSet, n: Narrowing<any, V>, k: unknown): V | undefined
export function carrier(s: AssumptionSet, n: Narrowing, k: unknown): AssumptionSet | undefined
export function leq(x: AssumptionSet, y: AssumptionSet): boolean               // algebraic
export function bindings(s: AssumptionSet): Iterable<Assumption>
```

- Each canonical `AssumptionChain` now carries a content-addressed
  `bindings: ReadonlyMap<Narrowing, ReadonlyMap<key, Assumption>>`
  built at intern-time (outer + extended-narrowing inner Map cloned;
  sibling inner Maps shared read-only).
- `leq` is algebraic subset-with-agreement via the bindings map —
  correctly detects rebuild-path supersets. No `extensions()` needed
  in the public API.
- Interner's `extend` / `rebuildWith` throw on conflicting value for
  an existing `(n, k)`; idempotent when `narrowing.eq` agrees.
- All call sites renamed mechanically; `hasAncestor(ctx, anc)` →
  `leq(anc, ctx)` arg swap happens in tests only (no production
  caller depended on parent-path semantics).

### PR 2 — Extract `assumption-bodies.ts`; kill prototype method

**New file:** `src/specialization/framework/assumption-bodies.ts`.

```ts
export function visibleBody(unit: Unit, s: AssumptionSet): readonly Stmt[]
export function forkBody(unit: Unit, s: AssumptionSet): Stmt[]
export function clearUnitBodies(unit: Unit): void
export function evictAt(unit: Unit, s: AssumptionSet): boolean   // was clearBodyIfForked
```

- Move the per-Unit `bodies` WeakMap and the helpers out of
  `assumption-chain.ts`.
- Drop `AssumptionSet.visibleBody` / `AssumptionSet.forkBody` methods.
  Delete `chainProto`. Callers read `bodies.visibleBody(unit, s)`.
- Not retirement-aware yet.

**Sequencing note:** PR 3 depends on this structurally. PR 3 adds
retirement-awareness to `visibleBody`; doing that before the prototype
method is removed reintroduces the coupling PR 2 exists to remove.

**Tests:** move `assumption-bodies.test.ts` cases; fork/visible
relationships unchanged, only call syntax changes.

### PR 3 — Retirement module

**New file:** `src/specialization/framework/retirement.ts`.

```ts
export class Retirement {
  retire(generator: AssumptionSet): void
  isRetired(s: AssumptionSet): boolean
}
```

- `retiredGenerators: Set<AssumptionSet>` holds minimal retired sets.
- `retire(r)`: `retiredGenerators.add(r)`. Idempotent. No cascade.
- `isRetired(c)`: `some(r in retiredGenerators, leq(r, c))` —
  algebraic membership, O(|R| × |r|). Correct for rebuild-path
  supersets because `leq` is algebraic.

**No late-arrival hook needed.** A chain extended from an already-
retired ancestor is a superset of a retired generator, so
`isRetired` returns true by the algebraic check. Interner stays
oblivious to retirement.

**`visibleBody` becomes retirement-aware.** Walk `s → empty` via
parent; skip any node where `isRetired(cur)` is true (don't return
its fork, don't stop at it). Falls through to nearest non-retired
ancestor with a fork or to `unit.body`.

**Worklist changes.** Delete `retiredNodes` field, pointwise
`isRetired`, `retireChain`, `redirectIfRetired`. Observation path
(`worklist.ts:1076-1098`) calls `retirement.retire(carrier)`.
Memo-bucket clearing + `futureDispatchContext` drop that previously
lived in `retireChain` move inline to the observation path where
the retirement is triggered — no subscriber protocol needed.

**Lazy body eviction.** Forked bodies at retired supersets are not
served (retirement-aware `visibleBody` skips them) and are reclaimed
when the unit releases. No eager cascade eviction.

**Behavior changes:**
- `isRetired` becomes algebraic-transitive (correct for rebuild
  supersets). Any test that implicitly benefited from the pointwise
  leak is rewritten.

**Tests:** `retirement.test.ts` asserting the filter laws.

- `retire(X); isRetired(Y)` for every `Y` with `leq(X, Y)`.
- `retire(X); !isRetired(Z)` for every `Z` with `!leq(X, Z)`.
- Retirement detects rebuild-path supersets (the bug the old parent-
  walk missed).
- `visibleBody(unit, Y)` for `Y` with a retired ancestor never returns
  a body from the retired subtree.
- Depth-3: retire `B`; `visibleBody(A⊑B⊑C)` returns `A`'s fork.
- Late-arrival: `retire(X)`; `extend(X, a) = Y`; `isRetired(Y)`.

### PR 5 — `dispatch.ts`; delete `specializedBodyFor`

**New file:** `src/specialization/framework/dispatch.ts`.

```ts
export function dispatchValid(unit: Unit, s: AssumptionSet): boolean
export function bodyToCompile(unit: Unit, s: AssumptionSet, topology: ReadonlyProgramTopology): readonly Stmt[]
```

- `dispatchValid`: `unit.funcAst instanceof FunctionDef` ∧
  `contextIsEntrySpecializable(unit, s)` ∧ `!retirement.isRetired(s)` ∧
  `directParamEntryGuardsFor(unit, s) !== undefined`.
- `bodyToCompile`: `source = bodies.visibleBody(unit, s)`;
  `pruned = pruneWithFactsAt(source, s, topology)`; return `pruned`.
  Always returns a body. Reference-equality against `unit.body` is
  the "specialization contributed?" check if any caller needs it.
- The pruning rewrite (currently `pruneStmts` in
  `speculative-clone.ts`) relocates here. `speculative-clone.ts` is
  deleted; its responsibilities split between `dispatch.ts`
  (body-for-chain) and `assumption-bodies.ts` (storage).
- `hasSpecializedBody` and `specializedBodyFor` delete.

**Four call-site rewrites:**
- `src/conductor/PyCseJitEvaluator.ts:75`
- `src/conductor/PySvmlJitEvaluator.ts:62`
- `src/tests/specialization/harness/jit-runners.ts:53` (SVML — also
  currently missing the retirement arg)
- `src/tests/specialization/harness/jit-runners.ts:115` (CSE — also
  currently missing the retirement arg)
- After this PR, retirement is internal to `dispatchValid` and can't
  be omitted.

Each site becomes:

```ts
if (!dispatchValid(unit, chain)) return undefined;
// SVML: return compiler.compileFunction(unit, bodyToCompile(unit, chain, topology));
// CSE:  return bodyToCompile(unit, chain, topology);
```

`PySvmlJitEvaluator` keeps the "always recompile" policy; the explicit
`dispatchValid` check surfaces the two SVML sites' policy asymmetry
that was previously hidden inside the `undefined` overload.

**Behavior changes in this PR:**
- The ancestor-fork-drop bug is fixed: `dispatchValid` and
  `bodyToCompile` are independent, so a dispatch-valid chain always
  surfaces ancestor forks.
- `bodyToCompile` is total; callers no longer conflate
  "no-speculation" with "dispatch-invalid."

**Tests:** `dispatch.test.ts` covering the `dispatchValid`
enumeration, the ancestor-fork-drop regression, and
`unit.body` immutability.

## Open concerns flagged during review

### Analysis-store retirement eviction

`retireChain` at `worklist.ts:437-448` evicts forked bodies and memo
buckets but does not call `clearContext` on `AnalysisStore`
partitions keyed under retired chains. The cascade in PR 3 expands the
problem: analysis-store cells at descendants of a retired chain will
accumulate without eviction.

This is real but orthogonal to the algebra refactor. Call-out for a
separate PR after PR 6: `AnalysisStore` registers a retirement
evictor that drops cells at each retired `s`. Tracked separately.

### `purityBlockAnalysis` import at worklist.ts:52

Framework→analysis direct import. Not resolved by any PR in this plan.
Candidate for post-refactor cleanup — the retirement-evictor protocol
in PR 4 is a template for how this should move out.

### Module naming

`assumption-algebra.ts` over `chain-lattice.ts`. The structure is not
a lattice (partial join) and chains in order theory are totally
ordered — neither word holds up. "Algebra" is honest: the module
exposes operations on a typed algebraic structure without naming a
specific classification that'd need qualification.

### "Fibration" / "presheaf"

Mentioned in internal discussion. Neither word appears in the
codebase and neither belongs in module docs. `assumption-bodies.ts`
is "body storage indexed by assumption sets," stated plainly.

## Non-goals

- Introducing explicit ⊤. The tax on fact-read sites outweighs the
  clarity gained. `extend` asserts on conflict; the worklist retires
  on conflict; the semilattice stays partial on join.
- Making the interner the single owner of the retirement filter.
  `retirement.ts` is its own module; the interner only provides
  `extensions` and the late-arrival hook.
- Serializing chains cross-process. Narrowing ordinals are per-process;
  no requirement to stabilize.
